# Bobo

Bobo 是一个运行在 Windows 和可信局域网内的轻量甘特图项目管理工具。它以“系统 -> 项目 -> 需求 -> 阶段”为主结构，并为阶段提供可分配、可关闭的问题与子任务清单。

## 运行环境

- Windows
- Node.js 18 或更高版本
- 不需要安装第三方运行依赖

启动：

```powershell
npm start
```

只启动服务而不自动打开浏览器：

```powershell
npm run start:no-open
```

默认地址为 [http://localhost:4177/](http://localhost:4177/)；服务会同时监听局域网网卡，并在终端打印可访问的 IP 地址。请在 Windows 防火墙中允许 Node.js 的专用网络访问。

## 首次使用与账户

第一次访问时会显示初始化页，第一位访问者创建管理员账户。账户信息保存在本机 `data/users.json`，密码以 Node.js scrypt 哈希保存，不会提交到仓库。

- 管理员：管理账户、创建和编辑全部项目内容、删除项目/需求/阶段/问题、在本机关闭服务。
- 成员：查看、新增和编辑项目内容，创建、分配、更新、关闭或重新打开问题。
- 用户账户不会物理删除，只能停用，以保留问题的历史负责人和关闭记录。
- 会话使用局域网 HTTP Cookie，服务重启或 24 小时后需要重新登录。

## 数据结构

```text
data/
├─ meta.json                       # schema 版本与全局 revision
├─ systems.json                    # 系统、系统日期标记、项目顺序
├─ users.json                      # 运行态账户（已忽略）
├─ users.example.json              # 无凭据示例
└─ projects/
   └─ <project-id>/
      ├─ project.json              # 项目、标记、需求、阶段与顺序
      └─ issues.json               # 该项目阶段下的问题/子任务
```

界面状态，例如选中的项目、折叠状态、日期范围和栏位宽度，只保存在浏览器按账户隔离的 `localStorage` 中，不会影响其他用户。

旧版 `data/projects.json` 会在新版服务首次启动时自动迁移；原文件会复制到 `data/backups/` 后改名为 `projects.json.migrated`。备份目录、迁移文件和账户文件均不参与 Git。

## 问题与阶段

双击甘特图阶段条或点击阶段编辑按钮，打开“阶段详情”和“待处理问题”页签。

每条问题包含：

- 标题、描述、状态：待处理 / 处理中 / 已关闭
- 单一负责人，可从启用成员中选择
- 创建人、创建时间、最后更新人和时间
- 关闭人和关闭时间

任意成员都可以关闭或重新打开问题。关闭动作由服务器写入当前登录账户和时间，浏览器不能伪造。阶段标题前的红点表示存在开放问题；没有开放问题时显示绿点。未来日期新建的阶段会自动生成一条未分配的“待处理：阶段名称”问题。

## 多人协作

- 所有保存带全局 revision；若其他用户已更新数据，旧页面的保存会返回冲突提示，而不会静默覆盖。
- 问题本身带版本号，两个用户同时修改同一问题时，后提交的一方会收到冲突提示。
- 页面每 5 秒检查一次 revision。没有打开编辑弹窗时会自动刷新；编辑中发现更新时会提示，保留当前输入。
