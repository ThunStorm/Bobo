# Bobo

Bobo 是一套面向可信局域网小团队的轻量项目管理系统。它以甘特图为主要工作区，组织“系统 -> 项目 -> 需求 -> 阶段”，并在阶段下维护负责人、进度和轻量 Jira 式问题。应用可在 Windows 上双击启动，浏览器访问，不依赖数据库、前端框架或第三方运行时包。

## 项目特征

- 甘特图主视图：日期横轴，系统、项目、需求、阶段纵向分层；支持折叠、拖动排序、日期标记、悬浮摘要和双击编辑。
- 轻量问题协作：问题支持待处理、处理中、已关闭，包含负责人、优先级、截止日期、评论及操作人/时间审计。
- 局域网头像登录：普通成员点击头像免密进入，管理员使用至少 4 位密码；登录列表按系统折叠，成员可关联一个或多个系统。
- 清晰权限边界：成员只能访问关联的系统；管理员管理账户与系统，并执行项目、需求、阶段和问题的结构性删除。
- 本地多文件数据：系统索引、账户、项目和问题分别保存为 JSON，采用原子写入、全局 revision 与实体 version，便于备份和排查。
- 零依赖运行：服务端只使用 Node.js 内置模块，前端为原生 HTML、CSS 和 JavaScript，适合 Windows 与可信内网。
- 克制的红色品牌主题：红色用于品牌、选择和主要交互；甘特阶段、状态和日期标记的业务颜色保持独立，不随主题色改变。

## 快速运行

要求 Windows 与 Node.js 18 或更高版本。

最简单的方式是双击仓库根目录的 `run.bat`。也可以在终端运行：

```powershell
npm start
```

只启动服务、不自动打开浏览器：

```powershell
npm run start:no-open
```

默认地址为 [http://localhost:4177/](http://localhost:4177/)。首次启动且没有有效管理员时，系统会进入独立初始化页；创建管理员后会自动进入工作台。服务默认监听局域网网卡，终端会打印其他设备可访问的 IP 地址。首次使用时需在 Windows 防火墙中允许 Node.js 的专用网络访问。

停止服务可以使用本机管理员工作台右上角的“关闭”，或在启动服务的终端按 `Ctrl+C`。如果端口被占用，请先关闭原服务进程，再重新运行 `run.bat`。

## 账户与登录

- 登录页按系统折叠普通成员，关联多个系统的成员会出现在对应的多个分组中；管理员集中显示在“管理员”分组。
- 普通成员由管理员创建，无密码，点击单字头像直接进入；管理员点击头像后输入密码。
- 管理员访问全部系统。普通成员至少关联一个系统，只能查看和操作其关联范围。
- 每个账户有一个可修改的单字头像。账户删除为逻辑删除，历史问题、评论、负责人和关闭记录仍保留原身份。
- 最后一名有效管理员不能删除、停用或降级，管理员也不能删除自己。
- 会话使用 HttpOnly、SameSite Cookie，服务重启或 24 小时后需要重新登录。

免密头像登录仅适合可信局域网。不要把当前配置直接暴露到互联网。

## 数据结构

```text
data/
├─ meta.json                       # schema 版本、全局 revision、更新时间
├─ systems.json                    # 系统、系统日期标记、项目顺序和版本
├─ users.json                      # 账户、头像、系统关联和密码哈希，Git 忽略
├─ users.example.json              # 无凭据示例
└─ projects/
   └─ <project-id>/
      ├─ project.json              # 项目、需求、阶段、标记和实体版本
      └─ issues.json               # 问题、评论和问题版本
```

个人选中项、折叠状态、日期范围和面板宽度保存在按账户隔离的浏览器 `localStorage`，不会写入共享业务数据。所有 JSON 写入先落临时文件再原子替换。旧版 `data/projects.json` 首次启动时会先备份到 `data/backups/` 再迁移。

备份时应在服务停止后复制整个 `data/` 目录。恢复时同样先停止服务，再整体替换，避免项目与 revision 不一致。

## 阶段与问题

在需求下新增阶段或双击甘特空白处时，阶段默认使用“自定义”模式；保存后阶段类型与标题一致。负责人既可从当前系统的有效账号中选择，也可直接输入外部人员姓名。阶段编辑弹窗使用右上角 `×` 或 `Esc` 关闭。

未来日期的新阶段会自动生成一条未分配的开放问题。阶段标题前的红点表示存在未关闭问题，绿点表示当前没有未关闭问题。问题支持：

- 标题、描述、状态、优先级和可选截止日期。
- 单一负责人，候选人按当前系统权限过滤。
- 创建、更新、关闭和重新打开的操作者与本地时间展示。
- 追加式评论；提交后不编辑、不删除，以保留审计历史。
- 状态、优先级、负责人和逾期筛选；筛选只影响当前阶段列表。

## 多人协作

浏览器每 5 秒检查全局 `revision`。没有编辑弹窗时自动刷新；编辑期间只提示外部更新，不覆盖当前输入。系统、项目、需求、阶段和问题各自携带 `version`，同一实体并发修改时服务端返回 `409`，前端可加载服务器版本或基于最新版重试。

`PUT /api/state` 保留为手动保存兼容入口。资源写入与问题审计应优先使用资源级 API；普通成员提交过滤后的状态时，服务端会合并其无权访问的系统，避免误删其他系统。

## 开发与验证

```powershell
node --test
node --check server.js
node --check lib/auth.js
node --check lib/data-store.js
node --check public/app.js
node --check public/collab.js
node --check public/login.js
git diff --check
```

浏览器验收使用独立 `BOBO_DATA_DIR` 和临时端口，不能修改真实运行数据。运行态 `data/users.json`、备份、迁移文件、临时测试目录以及本机业务数据改动均不得提交。
