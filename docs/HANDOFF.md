## 当前架构

Bobo 是可信局域网内使用的零依赖 Node.js 应用。服务端只使用 Node.js 内置模块，前端为原生 HTML、CSS 和 JavaScript。共享数据按系统索引、账户、项目和问题拆分为 JSON；全局 `revision` 用于更新轮询，实体 `version` 用于写入冲突校验。

```text
data/
├─ meta.json
├─ systems.json
├─ users.json              # 运行态账户，禁止提交
├─ users.example.json
└─ projects/<project-id>/
   ├─ project.json
   └─ issues.json
```

未经明确架构决策，不引入前端框架、数据库、构建工具或第三方运行时依赖。

## 本轮实现

### 按系统折叠登录账户

- `GET /api/auth/choices` 增加最小化的系统列表以及每个账户的 `systemIds`；仍不返回用户名、角色详情、密码字段或业务数据。
- 登录页使用原生 `<details>` 按系统折叠普通成员，第一组默认展开；多系统成员出现在各关联系统组中。
- 管理员只在“管理员”组展示一次；无系统关联的兼容账户进入“其他账户”。
- 账户区限制最大高度并独立滚动，用户数量增加时不会拉长整个登录页。

### 品牌与界面主题

- 产品副标题统一为“轻量项目管理系统”。
- 品牌、主操作、选中态、头像和焦点反馈由蓝绿色调整为克制红色。
- 甘特阶段条、日期格、问题状态、优先级、里程碑和拖拽状态等业务颜色保持原值；主题色不得覆盖这些语义颜色。
- 桌面与窄屏登录布局继续使用固定尺寸头像和响应式网格，不增加依赖。

### 文档

- README 重写为面向使用者的项目特征、运行、权限、数据、问题流程、协作与备份说明。
- 新增 `docs/BUILD_PROMPT.md`，记录从零构建或继续开发本系统的决策完整提示词。

## 既有关键能力

- 独立管理员初始化页；管理员密码至少 4 位，普通成员点击头像免密登录。
- 普通成员关联一个或多个系统，服务端对系统、项目、需求、阶段和问题接口执行访问校验。
- 账户逻辑删除，历史负责人、评论和关闭记录保留原用户身份。
- 阶段弹窗右上角 `×` 与 `Esc` 可直接关闭；新增阶段默认自定义类型，负责人支持系统用户建议和自由文本。
- 阶段问题支持分配、优先级、截止日期、评论、关闭和重新打开；关闭人和时间由服务端生成。
- 项目、需求、阶段和问题结构性删除仅管理员可用，并在服务端级联清理。

```powershell
node --test
node --check server.js
node --check lib/auth.js

node --check public/app.js
```

浏览器验收必须使用隔离数据目录和临时端口，至少检查：

- 管理员初始化、普通成员头像登录和管理员密码登录。
- 系统分组的展开/折叠、多人列表滚动、跨系统成员重复展示及管理员独立分组。
- 普通成员只看到关联的系统，跨系统 API 返回 `403`。
- 甘特折叠、拖动、阶段编辑、问题分配/评论/关闭/重新打开和并发冲突提示。
- 桌面与手机宽度下无溢出、遮挡或控制台错误。
- 红色只作用于主题，甘特业务颜色未发生变化。

## 已知边界

- 普通成员免密登录只适合可信局域网；知道地址的人可以选择任一普通成员身份。
- 服务使用 HTTP，没有 HTTPS、验证码、外网防护或项目级细粒度权限。
- JSON 模型适合单进程、小团队和低并发，不提供字段级合并。
- 部分新增和重命名流程仍使用原生 `prompt`，可逐步迁移到应用内对话框。
- 登录页按系统展示会让多系统成员重复出现，这是为了降低查找成本的预期行为。

## Git 与开发习惯

禁止提交 `data/users.json`、`data/backups/**`、迁移文件、隔离测试目录、日志、缓存或本机运行产生的业务数据变化。

每次新增功能或修复重大问题后，执行者判断风险范围并完成测试、更新 README、更新本交接文档、提交并推送当前开发分支。测试或推送失败时不得声明完成，必须在此记录原因与剩余工作。
