## 当前架构

Bobo 是可信局域网内使用的零依赖 Node.js 应用。服务端只使用 Node.js 内置模块，前端为原生 HTML、CSS 和 JavaScript。共享数据按系统索引、账户、项目和问题拆分为 JSON；全局 `revision` 用于更新轮询，实体 `version` 用于写入冲突校验。

```text
data/
├─ meta.json
├─ systems.json
├─ users.json              # 运行态账户，禁止提交
├─ users.example.json
└─ projects/<project-id>/
   ├─ project.json
   └─ issues.json
```

未经明确架构决策，不引入前端框架、数据库、构建工具或第三方运行时依赖。

## 前轮实现：周期交接、周待办与新增比较（2026-10-28）

- 明确三类用途：状态概览汇报当前所选内容的阶段进展，不做历史回溯；工作交接和 Todo 以周期内未完成事项为主，默认本周（周一至周日），提供下周/全部日期/自定义开始结束日期。
- 按用户确认的口径筛选：问题按截止日落区间内，阶段提醒按计划区间相交，包含首尾、精确到本地日。无有效截止日期默认排除并计数；期前遗留与无日期事项各有显式开关，默认关闭。日期不完整的阶段使用有效结束日并标注；保留全阶段问题去重规则，不因筛选造成重复提醒。
- 周期清单的摘要、待办、风险、完成清单和各格式输出共用同一筛选；状态概览增加阶段进展/备注，CSV 导出阶段和问题的状态明细，不再默认导出 Todo。交接将交接待办放在首位，完成清单默认不附带；父阶段暂停或已完成但问题未关闭的风险附在相关问题上。
- 新增纯函数与模板元数据：`weekRange`、`createBaseline`、`parseBaselineHtml`；HTML 内嵌不可执行的版本化基准模板。只导出本次授权/筛选内待办的稳定 ID 和内容指纹，基准读取采用限定模板文本提取及 JSON 校验，不创建或挂载导入文件的 DOM，也不执行其中脚本/加载资源。仅支持新版 Todo/交接 HTML，文件上限 2 MiB，不将旧文件视作空基准。
- 比较仅用于同范围、同周期和相同附加选项。导入时校验系统/项目 ID、有效日期、时间、重复/越界 ID 等，并恢复基准的日期条件；条件变化后清除比较。新增、内容变更、已有及本次未出现分别计数；“新增纳入”不等于实际新建，本次未出现不推断已删除。比较不依赖名称，因此系统/项目改名不破坏 ID 匹配。
- 待办支持风险/截止日优先、创建记录倒序和本次新增在前。阶段没有可靠创建时间，使用基准比较识别新增提醒；记录时间排序只使用问题已有时间，历史迁移时间的限制有明确提示。人工勾选不参与原始业务状态或新增判断。
- 区间、口径、排序、基准时间/revision 及变化标签进入预览、Markdown、CSV、HTML 和 PDF；导出文件名包含区间与 revision。离线保存勾选副本会保留基准模板，可用于下一次比较。导入基准只在当前弹窗内存中保留，关闭清空，不上传或存储。
