## 当前架构

Bobo 是可信局域网内使用的零依赖 Node.js 应用，前端为原生 HTML、CSS 和 JavaScript，数据按系统、项目和问题拆分为 JSON 文件。不得在没有同步架构决策、README 和本文件的情况下引入前端框架、数据库、构建工具或第三方运行时依赖。

```text
data/
├─ meta.json
├─ systems.json
├─ users.json              # 运行时账户，禁止提交
├─ users.example.json
└─ projects/
   └─ <project-id>/
      ├─ project.json
      └─ issues.json
```

多人协作继续使用全局 `revision` 轮询和实体 `version` 写入校验。`PUT /api/state` 仅作为兼容保存入口；问题、评论和审计字段必须通过资源 API 修改。

## 本轮实现

### 独立头像登录

- 登录从工作台移到 `/login.html`，主应用未登录时直接跳转，不再把登录表单和工作台堆在同一页面。
- 没有有效管理员时显示初始化表单；管理员密码至少 4 位，不要求字符组合，创建后直接进入工作台。
- 普通账号没有密码，点击头像立即登录；管理员点击头像后输入密码。
- 账户头像为单个字符，本人和管理员均可修改。
- 登录页已验证桌面和 390px 手机布局，控制台无错误。

### 账户与系统权限

`users.json` 升级到 schema 2，账户增加 `avatarText`、`systemIds` 和 `deletedAt`。旧管理员保留密码；旧普通账号自动移除密码并默认关联迁移时的全部系统。

- 管理员访问全部系统，可创建系统和管理账户。
- 普通账号至少关联一个系统，只能读取和修改关联系统，跨系统 API 返回 `403`，不能创建系统或执行结构性删除。
- 问题负责人只能选择当前系统关联的有效账户或管理员。
- 删除账户为逻辑删除，会话立即失效并从登录页消失；历史负责人、评论和关闭记录仍显示原身份。
- 最后一名管理员不可删除、停用或降级，管理员不可删除自己。
- 删除系统前若会导致普通账号没有任何系统，服务器要求先调整账户关联。
- 普通账号使用兼容 `/api/state` 保存时，服务器合并无权访问的系统，防止过滤后的状态覆盖其他系统。

### 新增与调整接口

```text
GET                       /api/auth/choices
POST                      /api/auth/select
PATCH                     /api/users/me/avatar
DELETE                    /api/users/:userId
```

`POST/PATCH /api/users` 现在接受 `avatarText`、`systemIds`、角色和管理员密码。`/api/bootstrap`、系统和资源接口都按当前账户过滤或校验系统访问范围。

## 已知边界

- 无密码头像登录只适合可信局域网；知道地址的任何局域网用户都能选择普通账号身份。
- 管理员密码和会话仍通过局域网 HTTP 传输，没有 HTTPS、验证码或外网防护。
- JSON 文件模型只适合单进程、小团队、低并发使用。
- 冲突处理为实体级重试，不提供字段级合并。
- 部分新增和改名流程仍使用原生 `prompt`，后续可迁移为应用内对话框。

## Git 与开发习惯

禁止提交 `data/users.json`、`data/backups/**`、`data/projects.json.migrated`、隔离测试目录、日志、缓存或本机运行产生的业务数据。

每次新增功能或修复重大问题后，由执行者判断是否达到重大变更范围；若达到，必须依次完成测试、更新 README、更新本交接文档、提交 Git 并推送当前开发分支。测试或推送失败时不得声明完成，必须记录失败原因和剩余工作。
