# Bobo 系统构建计划与提示词

本文既是产品实现计划，也是可以交给编码代理的需求提示词。目标是复现或继续开发当前 Bobo，而不是制作营销页面。

## 1. 产品目标

为 Windows 与可信局域网小团队实现一套极轻量项目管理系统。第一屏就是可工作的甘特图：横轴为日期和关键节点，纵轴为系统、项目、需求、阶段。用户可以折叠层级、拖动排序、双击编辑，并在阶段下按轻量 Jira 逻辑处理问题。

系统应做到：双击可运行、浏览器可访问、局域网多用户协作、数据易读易备份、没有数据库和第三方运行时依赖。

## 2. 技术约束

- Node.js 18+，服务端仅使用 `node:http`、`fs`、`path`、`crypto` 等内置模块。
- 前端仅使用原生 HTML、CSS、JavaScript，不使用框架、包管理依赖或构建步骤。
- Windows 提供 `run.bat`，macOS 提供可双击的 `run.command`；启动后自动打开浏览器，支持 `--no-open`。默认监听 `0.0.0.0:4177`，支持环境变量覆盖主机、端口和数据目录；端口占用时报错退出，不把未知服务当作 Bobo。
- 所有业务数据保存为 UTF-8 JSON，临时文件写完后原子替换。
- 页面面向重复操作和信息扫描，布局紧凑、稳定，不制作落地页或装饰性卡片堆叠。
- 品牌主题使用克制红色；甘特条、状态、日期和优先级拥有独立语义颜色，禁止跟随主题色重染。

## 3. 数据模型

```text
data/
├─ meta.json                 # schemaVersion, revision, updatedAt
├─ systems.json              # systems, markers, projectIds, order, version
├─ users.json                # users schema；运行文件不提交
└─ projects/<project-id>/
   ├─ project.json           # project, requirements, stages, markers, versions
   └─ issues.json            # issues, comments, versions
```

账户包含 ID、唯一用户名、显示名、单字头像、角色、启用状态、系统 ID 数组、密码盐/哈希、删除时间。普通成员不保存密码；管理员密码用 Node.js `scrypt` 保存。业务实体携带递增 `version`，全局写入递增 `revision`。

个人选中项、折叠、日期范围、面板宽度保存在按用户隔离的 `localStorage`，不得进入共享 JSON。

## 4. 登录与权限

- 没有有效管理员时显示独立初始化页；首位管理员密码至少 4 位，创建后自动建立会话并进入工作台。
- 已初始化时，登录页按系统使用可折叠分组展示普通成员。成员关联多个系统时可在多个组中出现；管理员单独成组。
- 普通成员点击头像直接登录；管理员选择头像后输入密码。
- 使用随机 HttpOnly、SameSite Cookie；会话内存保存 24 小时，服务重启后失效。
- 管理员访问全部系统，可管理账户、系统和结构性删除。成员只能访问关联系统，可新增和编辑业务内容，但不能创建系统或删除项目、需求、阶段、问题。
- 账户删除为逻辑删除并立即终止其会话。最后一名有效管理员不能删除、停用或降级；管理员不能删除自己。
- 所有资源 API 在服务端校验系统范围，不能依赖前端隐藏控件作为权限措施。

## 5. 甘特工作区

- 顶栏：Bobo、系统选择、当前账户、保存、本机管理员关闭服务。
- 左栏：项目列表、日期范围、日期标记；左栏和甘特区独立滚动。
- 甘特层级：项目 -> 需求 -> 阶段。每层可折叠；阶段可拖动排序。
- 点击项目卡片任意非编辑位置均能选择；选择时只让右侧项目行定位，不改变左侧列表滚动位置。
- 阶段条悬浮展示摘要，双击打开编辑弹窗。标签列必须有不透明背景，横向滚动时甘特条不能透到文字下面。
- 新增阶段默认“自定义”，保存时 `type` 和 `title` 都等于输入标题；标准阶段允许类型和标题不同。
- 阶段负责人为可输入的建议控件：候选为管理员和当前系统有效成员，同时允许输入外部姓名。
- 弹窗右上角只保留一个 `×`，并支持 `Esc`；关闭不触发表单校验，也不删除已创建实体。

## 6. 问题工作流

每个阶段有零到多条问题。问题包含标题、描述、状态、单一负责人、优先级、截止日期、创建/更新/关闭人员和时间、追加式评论。

状态为待处理、处理中、已关闭。任意有权成员可分配、处理、关闭和重新打开；关闭人及关闭时间由服务端当前会话生成，客户端不能伪造。重新打开时清空当前关闭信息。已删除或停用用户继续在历史记录中显示，但不能成为新负责人。

未来日期的新阶段自动创建一条开放且未分配的问题。阶段红点由“存在未关闭问题”派生，无开放问题时显示绿点，不重复保存布尔状态。

## 7. 保存与并发

- 前端每 5 秒只检查 revision；无编辑时自动刷新，编辑时提示外部更新并保留输入。
- 资源级接口接收实体版本。版本不匹配返回 `409` 和服务器最新实体，不静默覆盖。
- 项目、需求或阶段删除时在服务端级联删除关联问题。
- 兼容 `PUT /api/state` 时，普通成员提交的过滤状态必须与服务器上的未授权系统合并。

## 8. 实施顺序

1. 建立多文件数据仓库、schema 校验、原子写入与旧单文件迁移。
2. 建立管理员初始化、头像登录、会话、账户管理和系统权限。
3. 实现系统/项目/需求/阶段/标记/问题资源 API、版本冲突与级联删除。
4. 构建紧凑甘特工作区、折叠、独立滚动、拖动排序、弹窗编辑和响应式布局。
5. 实现问题列表、详情、筛选、分配、评论、关闭与审计展示。
6. 加入 revision 轮询、冲突处理、Windows 启停和局域网地址提示。
7. 完成自动化测试、隔离浏览器验收、README 与交接文档。

## 9. 验收标准

- `node --test`、所有关键 `node --check` 和 `git diff --check` 通过。
- 初始化管理员后自动进入工作台；普通成员头像直登，管理员密码登录。
- 登录分组可展开/折叠，多用户时页面不无限增长，手机与桌面无溢出。
- 普通成员跨系统访问返回 `403`，结构性删除返回 `403`；管理员操作正常。
- 甘特折叠、排序、横向滚动、日期标记、阶段编辑和问题状态均可靠。
- 两名用户编辑不同实体不会互相覆盖，编辑同一实体显示冲突。
- 停用/删除账户后会话失效，历史审计身份不丢失。
- 红色只改变品牌主题；甘特业务颜色与状态语义保持原值。
- 运行数据和凭据不进入 Git。

## 10. 可直接使用的提示词

```text
请在当前仓库中实现 Bobo：一套面向 Windows 与可信局域网小团队的零依赖轻量项目管理系统。先阅读现有 README、交接文档和代码，尊重当前架构与数据，不覆盖未提交的运行态数据。

使用 Node.js 18+ 内置模块和原生 HTML/CSS/JavaScript，不引入数据库、前端框架、第三方运行时包或构建步骤。系统以甘特图为首屏，支持系统、项目、需求、阶段层级，日期标记、折叠、拖动排序、悬浮摘要、双击编辑、负责人和工时。阶段下实现轻量 Jira 式问题：状态、单一负责人、优先级、截止日期、评论、关闭/重新打开及操作人时间审计。

数据拆分为 meta.json、systems.json、users.json、projects/<id>/project.json 和 issues.json，使用 schema 校验、原子写入、全局 revision 与实体 version。实现旧数据迁移和备份。个人视图状态只存 localStorage。

没有管理员时提供独立初始化页，管理员密码至少 4 位并用 scrypt 哈希。普通成员无密码，登录页按系统折叠头像列表，点击头像登录；管理员输入密码。成员可关联多个系统且只能访问关联范围，管理员访问全部系统并管理账户。账户逻辑删除，历史审计保留。所有权限必须在服务端校验。

界面应紧凑、安静、适合高频工作。品牌主题使用克制红色，但不要改变甘特条、日期、状态、优先级等已有业务颜色。不要制作营销页，不要把卡片嵌套在卡片中，固定控件尺寸并验证桌面与手机布局。

完成后补充 node:test 覆盖迁移、认证、权限、级联删除、问题生命周期和并发冲突；使用隔离 BOBO_DATA_DIR 进行浏览器验收。运行全部语法检查和 git diff --check，更新 README 与 docs/HANDOFF.md。测试失败或无法推送时明确说明，不得声称完成。
```
